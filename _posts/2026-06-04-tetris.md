## 프로젝트 목표

C언어로 작성된 테트리스 코드를 C++로 옮기면서 객체지향적인 구조로 다시 설계하고 테트리스라는 주제에 맞는 새로운 기능을 추가로 구현하는 프로젝트였습니다.

## 구조

블록의 공통 동작(그리기, 지우기, 이동, 회전)은 추상 클래스 `Block`에 두고 블록 종류마다 모양만 다른 파생 클래스로 나눴습니다.

```
Block (추상 클래스)
├── IBlock, OBlock, TBlock, JBlock, LBlock, SBlock, ZBlock   ← 기본 블록
├── PlusBlock, UBlock, WBlock                               ← 5칸 특수 블록
└── BombBlock                                               ← 폭탄 블록
```

각 파생 클래스는 순수 가상 함수 `getCell()`로 자기 모양만 알려 주고 화면에 그리는 일은 부모 클래스가 공통으로 처리합니다. 덕분에 새 블록을 추가할 때 모양 정의만 추가하면 되는 구조가 되었습니다.

## 맡은 역할

- 팀원들이 각자 구현한 코드를 하나의 병합본으로 통합 (35개 파일)
- 구름(시야 방해) 기능 구현과 버그 수정
- U자 블록 오류 수정
- 일시정지(pause) 버그 수정
- 코드 전반에 주석 작성

## 주요 구현: 구름 기능

제가 구현한 기능으로, 일정 줄 수를 지울 때마다 보드 일부가 구름(`~~`)으로 가려져 블록이 잘 보이지 않게 되는 방해 요소입니다.

- 누적으로 지운 줄 수가 기준을 넘으면 구름이 나타나고 3줄을 더 지우면 사라집니다.
- 처음에는 20줄마다 고정으로 나오던 구름을, `15 - level`줄 뒤에 나타나도록 바꿔 레벨이 오를수록 더 자주 나오게 조정했습니다.

## 문제와 해결

구현과 테스트 과정에서 발견하고 해결한 문제들입니다.

### 1. 블록이 지나가면 구름에 구멍이 뚫리는 문제

- **문제**: 블록이 구름 영역을 지나 내려가면 블록이 있던 자리가 검정으로 지워져 구름에 구멍이 생겼습니다.
- **원인**: 블록을 지우는 함수가 위치와 상관없이 항상 검정색으로 칸을 덮고 있었습니다.
- **해결**: 지우려는 칸이 구름 영역 안이면 검정 대신 구름 문자(`~~`)를 다시 그리도록 바꿨습니다. 떨어질 위치를 미리 보여 주는 고스트 블록에도 같은 처리를 넣었습니다.

```cpp
if (cloudActive && bx >= sx && bx <= ex && by >= sy && by <= ey) {
    // 구름 영역 안이면 지운 자리에 구름을 다시 그린다
    ConsoleUI::setColor(COLOR_WHITE);
    ConsoleUI::gotoxy(bx * 2 + AB_X, by + AB_Y);
    std::cout << "~~";
} else {
    ConsoleUI::eraseBlock(bx, by, color);
}
```

### 2. 쓰레기 줄이 올라오면 구름 위치가 어긋나는 문제

- **문제**: 아래에서 쓰레기 줄이 올라와 보드 전체가 한 칸 위로 밀릴 때, 구름만 제자리에 남아 위치가 어긋났습니다.
- **원인**: 보드의 칸들은 함께 이동하지만 구름 좌표는 따로 저장된 값이라 자동으로 갱신되지 않았습니다.
- **해결**: 쓰레기 줄이 올라올 때 구름의 Y좌표도 함께 1씩 올리고 화면 밖으로 나가지 않도록 최솟값을 1로 고정했습니다.

### 3. 일시정지 중에도 쓰레기 줄이 올라오는 문제

- **문제**: 게임을 일시정지해도 쓰레기 줄이 계속 올라왔습니다.
- **원인**: 쓰레기 줄 생성 조건에 일시정지 상태 검사가 빠져 있었습니다.
- **해결**: 조건에 `!paused`를 추가했습니다.

```cpp
if (!gameOver && !paused && frame > 0 && frame % GARBAGE_SPEED == 0) {
```

## 아쉬운 점

### 인코딩 차이로 인한 병합의 어려움

프로젝트는 여러 개의 코드 파일로 나뉘어 있었는데, 팀원마다 작업 환경이 달라서 처음 파일을 만들 때부터 서로 다른 인코딩으로 Git에 올라왔습니다. 그래서 Git에서 코드를 불러와 실행하면 인코딩 오류가 발생했고 최종 코드가 나오기 전까지는 코드를 받아올 때마다 각 파일을 UTF-8로 다시 인코딩한 뒤 실행해야 했습니다. 이 문제는 프로젝트 막바지에 팀원이 파일 인코딩을 정리하면서 해결되었습니다.

같은 작업을 매번 반복하면서 프로젝트를 시작할 때 인코딩 같은 공통 작업 환경을 먼저 정해 두는 것이 중요하다는 것을 느꼈습니다. 이후 팀 프로젝트에서는 시작 단계에서 이런 규칙부터 맞추고 싶습니다.

### 객체지향 설계를 연습할 기회가 적었던 점

객체지향프로그래밍 과목의 프로젝트였지만 제가 맡은 부분은 병합과 버그 수정, 기능 조정이 중심이어서 클래스 설계나 상속 구조를 직접 고민하며 연습할 기회는 상대적으로 적었습니다. 다음 프로젝트에서는 설계 단계부터 참여해 보고 싶습니다.

## 배운 점

### Git을 활용한 협업

다른 사람들과 Git으로 협업한 것은 이번이 처음이었습니다. 여러 사람의 코드를 하나로 병합하고 충돌을 해결하는 과정을 직접 겪으면서 Git을 통한 협업 방식을 익힐 수 있었습니다.

### 팀의 방향을 함께 맞춰 가는 것

개인 프로젝트와 달리 팀 프로젝트에서는 제가 생각하는 방향과 팀이 나아가는 방향이 다를 수 있었습니다. 이런 상황에서 무엇을 먼저 생각하고 어떻게 맞춰 가야 하는지 고민해 보는 계기가 되었습니다.
