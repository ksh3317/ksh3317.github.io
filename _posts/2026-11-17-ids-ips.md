## 들어가며

이 글에서는 IDS와 IPS를 비교하며 두 시스템에 대해 정리한다.

## 한눈에 보는 IDS와 IPS

| 구분 | IDS | IPS |
|---|---|---|
| 이름 | Intrusion Detection System | Intrusion Prevention System |
| 우리말 | 침입 탐지 시스템 | 침입 방지 시스템 |
| 하는 일 | 공격을 탐지해서 알린다 | 공격을 탐지해서 차단한다 |
| 배치 방식 | 수동 (트래픽 복사본을 분석) | 인라인 (트래픽이 직접 통과) |
| 비유 | 건물의 CCTV | 건물 입구의 보안 검색대 |

두 시스템은 같은 탐지 기술을 쓸 수 있다. 차이는 트래픽을 어디에서 받느냐와 탐지한 뒤에 무엇을 하느냐에 있다. IDS는 경고와 기록을 남기고, IPS는 공격을 차단하면서 경고와 기록도 함께 남긴다.

## 동작 원리

### 처리 흐름

IDS와 IPS는 트래픽을 받아서 분석하고 대응하기까지 비슷한 단계를 거친다.

```text
트래픽 수집 → 전처리 → 탐지 → 대응 → 기록
```

| 단계 | 하는 일 | IDS | IPS |
|---|---|---|---|
| 수집 | 분석할 트래픽을 받음 | 미러링된 복사본을 받음 | 통과하는 원본을 직접 받음 |
| 전처리 | 쪼개진 패킷을 다시 합치고 프로토콜 형식에 맞게 해석 | 같음 | 같음 |
| 탐지 | 탐지 엔진이 공격 여부를 판단 | 같음 | 같음 |
| 대응 | 탐지 결과에 따라 조치 | 경고 | 차단과 경고 |
| 기록 | 탐지 내용을 로그로 남김 | 같음 | 같음 |

전처리 단계가 필요한 이유는 공격자가 공격 코드를 여러 패킷에 나눠 보내서 탐지를 피하려 하기 때문이다. 이를 단편화 공격이라고 한다. 패킷을 하나씩만 보면 공격 패턴이 보이지 않으므로, 탐지 전에 원래 데이터 흐름으로 재조립한다.

표에서 보듯 두 시스템은 수집과 대응 단계에서만 다르고, 탐지의 핵심인 전처리와 탐지 단계는 같다.

### 공통: 공격을 판단하는 방법

탐지 방식은 자료마다 분류가 조금씩 다르다. 이 글에서는 미국 국립표준기술연구소(NIST)의 IDS/IPS 가이드인 SP 800-94의 분류를 따른다.

| 방식 | 판단 기준 | 잘 잡는 것 | 약점 |
|---|---|---|---|
| 서명 기반 | 알려진 공격 패턴과 일치하는가 | 이미 알려진 공격 | 제로데이 공격, 변형된 공격 |
| 이상 기반 | 정상 기준에서 크게 벗어났는가 | 처음 보는 공격 | 정상이지만 평소와 다른 활동 (오탐) |
| 상태 기반 프로토콜 분석 | 통신이 프로토콜 표준의 순서와 형식을 따르는가 | 프로토콜 규칙을 어기는 공격 | 자원 소모가 크고 프로토콜마다 프로파일이 필요 |

**서명 기반 탐지**는 알려진 공격의 특징을 규칙(rule)으로 만들어 두고 트래픽과 비교하는 패턴 매칭 방식이다. 이 특징을 서명(시그니처)이라고 하고, 오용 탐지라고 부르기도 한다. 일치하는 규칙이 있어야 잡을 수 있어서, 아직 서명이 만들어지지 않은 제로데이 공격은 탐지하지 못한다. 공격 코드를 조금만 바꿔도 패턴이 달라질 수 있어서 규칙을 꾸준히 업데이트해야 한다.

**이상 기반 탐지**는 일정 기간 동안 트래픽 양, 사용 포트, 접속 시간대, 프로토콜 비율 같은 정보를 관찰해서 정상 상태의 프로파일을 만든다. 이 기준을 베이스라인이라고 한다. 이후 통계 기법이나 기계 학습으로 현재 상태와 베이스라인을 비교해서 크게 벗어나면 공격으로 의심한다. 보안 업체 자료에서 소개하는 "행동 분석"도 평소와 다른 행동의 흐름을 찾는다는 점에서 이 방식의 한 갈래로 볼 수 있다.

**상태 기반 프로토콜 분석**은 프로토콜 표준 문서(RFC)를 바탕으로 만든 정상 동작 프로파일과 실제 통신을 비교한다. 통신이 지금 어느 단계에 있는지(상태)를 추적하면서 보기 때문에, 예를 들어 인증 전에 인증 후에만 쓸 수 있는 명령이 들어오면 이상으로 판단한다.

실제 제품은 이 방식들을 함께 써서 서로의 약점을 보완한다.

### 차이: 탐지한 뒤의 대응

| 구분 | IDS | IPS |
|---|---|---|
| 트래픽을 보는 방식 | 복사본을 옆에서 분석 | 원본이 직접 통과 |
| 공격 탐지 시 | 관리자에게 경고 | 차단하고 관리자에게 경고 |
| 구체적인 대응 | 경고 알림, 로그 기록 | 패킷 폐기, 세션 종료, 출발지 IP 차단, 경고 알림, 로그 기록 |
| 대응 시점 | 공격 패킷이 이미 목적지에 도착한 뒤 | 공격 패킷이 목적지에 닿기 전 |

IDS는 복사본을 보기 때문에 탐지했을 때는 원본 패킷이 이미 목적지에 도착해 있다. 일부 IDS 제품은 TCP 연결을 끊는 RST 패킷을 보내거나 방화벽에 차단을 요청하는 기능도 있지만, 공격이 끝난 뒤일 수 있어서 확실한 차단 수단은 아니다. IPS는 원본이 자신을 통과해야 하므로 공격 패킷을 목적지에 보내지 않고 그 자리에서 버릴 수 있다.

## 유형

유형은 "어디에서 무엇을 보느냐"에 따른 분류다. 이름의 앞 글자가 위치를 나타내고(N은 네트워크, H는 호스트, W는 무선), 뒤가 IDS면 탐지만, IPS면 차단까지 한다.

| 유형 | 설치 위치 | 분석 대상 | IDS일 때 | IPS일 때 |
|---|---|---|---|---|
| 네트워크 기반 (NIDS / NIPS) | 네트워크 구간 (센서 장비) | 구간을 지나는 패킷 | 공격 패킷을 탐지해 경고 | 공격 패킷을 폐기 |
| 호스트 기반 (HIDS / HIPS) | 서버, PC (에이전트 프로그램) | 로그, 파일, 프로세스, 시스템 호출 | 이상 변경을 탐지해 경고 | 악성 실행과 변경을 차단 |
| 무선 (WIDS / WIPS) | 무선 신호 범위 (무선 센서) | 무선랜 통신 | 비인가 AP를 탐지해 경고 | 비인가 AP와의 연결을 끊음 |
| 네트워크 행동 분석 (NBA) | 네트워크 | 플로우 정보 (통신 흐름 요약) | 흐름 이상을 탐지해 경고 | 방화벽, 라우터 설정을 바꿔 차단 |

**네트워크 기반**은 센서 하나로 그 구간에 연결된 여러 시스템을 한꺼번에 감시할 수 있다. 대신 HTTPS처럼 암호화된 트래픽은 패킷에서 실제 데이터가 담긴 부분인 페이로드를 볼 수 없다. 대표적인 오픈소스 도구로 Snort와 Suricata가 있고, 둘 다 설정에 따라 IDS 모드와 IPS 모드로 쓸 수 있다.

**호스트 기반**은 각 시스템에 설치한 에이전트가 로그, 프로세스, 시스템 호출을 감시한다. 중요한 시스템 파일이 바뀌었는지 확인하는 파일 무결성 모니터링(FIM)이 대표적인 기능이다. 대표적인 도구로 OSSEC과 Wazuh가 있다.

**무선**은 허가받지 않고 설치된 무선 공유기(비인가 AP)나 정상 공유기를 흉내 내는 가짜 AP처럼 무선 구간에서만 생기는 위협을 잡는다. **네트워크 행동 분석**은 패킷 내용 대신 NetFlow 같은 플로우 정보, 즉 누가 누구와 언제 얼마나 통신했는지를 요약한 정보를 분석해서 DDoS나 스캔을 잡는다.

탐지 방식과 유형은 서로 다른 기준이다. 네트워크 기반 IDS가 서명 기반을 쓸 수도 있고 이상 기반을 쓸 수도 있다.

## 활용 방법

### 배치 방식

IDS와 IPS의 활용이 나뉘는 출발점은 네트워크에 놓이는 방식이다.

```text
[IDS: 수동 방식]
인터넷 ── 방화벽 ── 스위치 ── 서버
                     │
                     └─ (복사본) ─ IDS

[IPS: 인라인 방식]
인터넷 ── 방화벽 ── IPS ── 스위치 ── 서버
```

| 구분 | IDS | IPS |
|---|---|---|
| 배치 방식 | 수동 (passive, out-of-band) | 인라인 (inline) |
| 트래픽 경로 | 원본 트래픽은 IDS를 거치지 않음 | 모든 트래픽이 IPS를 통과 |
| 트래픽을 받는 방법 | 스위치의 포트 미러링(SPAN)이나 네트워크 탭(TAP)으로 복사 | 네트워크 회선 사이에 직접 연결 |
| 통신 지연 | 없음 | 검사 시간만큼 발생 |
| 잘 맞는 일 | 감시, 기록, 분석 | 실시간 차단 |

포트 미러링은 스위치가 특정 포트로 오가는 트래픽을 분석용 포트로 똑같이 복사해 주는 기능이고, 탭은 회선 중간에 끼워서 트래픽을 복사하는 전용 장비다. IDS는 복사본만 보기 때문에 원본 통신에 개입할 수 없지만, 잘못 판단해도 통신에 영향을 주지 않는다. IPS는 통신 경로 위에 있어서 공격을 그 자리에서 막을 수 있지만, 잘못 판단하면 정상 통신도 막힌다. 아래 환경들에서 두 시스템의 역할이 나뉘는 이유도 이 차이에서 나온다.

### 네트워크 환경

네트워크 트래픽은 외부와 내부 사이를 오가는 남북(north-south) 트래픽과, 내부 시스템끼리 오가는 동서(east-west) 트래픽으로 나눠 볼 수 있다. 외부에서 들어오는 트래픽에는 공격이 섞여 있을 가능성이 높아서 닿기 전에 막는 것이 중요하다. 반대로 내부 트래픽은 대부분 정상 업무라서 잘못 막았을 때의 피해가 더 크다. 그래서 외부 경계에는 IPS를, 내부에는 IDS를 두는 구성이 대표적이다.

**IDS 활용**: 내부 스위치에 미러링으로 연결해 동서 트래픽을 감시한다. 경계를 통과해 이미 들어온 공격자가 내부 시스템을 옮겨 다니며 권한을 넓혀 가는 측면 이동(lateral movement)을 찾는 데 쓴다. 남긴 경고와 로그는 사고가 난 뒤 경위를 밝히는 포렌식 자료가 된다. 새로 만든 탐지 규칙을 차단에 쓰기 전에 오탐이 없는지 검증하는 용도로도 쓴다.

**IPS 활용**: 방화벽 뒤에 인라인으로 두고 외부에서 들어오는 공격을 차단한다. 보안 패치를 바로 적용하기 어려운 취약점이 있을 때, 그 취약점을 노리는 공격만 먼저 막는 가상 패치(virtual patching)에도 쓴다. 감염된 내부 시스템이 공격자의 명령 제어(C2) 서버와 주고받는 통신을 차단하는 데도 쓴다.

| 구분 | IDS | IPS |
|---|---|---|
| 위치 | 내부 네트워크 (미러링) | 외부 경계 (방화벽 뒤, 인라인) |
| 주로 보는 트래픽 | 동서 트래픽 | 남북 트래픽 |
| 활용 | 측면 이동 탐지, 포렌식 자료 확보, 규칙 검증 | 외부 침입 차단, 가상 패치, C2 통신 차단 |

대규모 DDoS는 IPS로 막기 어렵다. 트래픽이 회선 대역폭 자체를 가득 채우면 IPS에 닿기 전에 통신이 마비되고, 모든 트래픽을 검사하는 IPS가 오히려 병목이 되기도 한다. 그래서 대규모 DDoS는 IPS보다 앞단의 전용 방어 장비나 통신사, 클라우드의 DDoS 방어 서비스가 맡는다.

### 호스트, 서버 환경

네트워크 센서는 회선을 지나는 패킷만 볼 수 있어서, 암호화된 통신의 내용이나 시스템 내부에서 일어나는 일은 알기 어렵다. 고객 정보를 저장한 데이터베이스 서버처럼 중요한 서버에는 호스트 기반 제품을 설치해서 이 빈틈을 채운다.

**IDS 활용**: 서버의 로그, 접속 기록, 중요 파일의 변경을 감시한다. 네트워크에서 공격 시도가 탐지됐을 때 그 공격이 실제로 성공했는지 서버 안에서 확인할 수 있다. 사고가 난 뒤에는 서버에서 어떤 프로세스가 실행되고 어떤 파일이 바뀌었는지 밝히는 자료가 된다.

**IPS 활용**: 서버 안에서 의심스러운 프로세스가 실행되거나 중요한 파일과 설정이 바뀌려고 하면 그 자리에서 막는다. 네트워크 IPS를 우회해 들어온 공격도 서버에서 실제로 실행되는 시점에 차단할 수 있다.

| 구분 | IDS | IPS |
|---|---|---|
| 위치 | 중요 서버 (에이전트 설치) | 중요 서버 (에이전트 설치) |
| 주로 보는 것 | 로그, 접속 기록, 파일 변경 | 프로세스 실행, 파일과 설정 변경 시도 |
| 활용 | 공격 성공 여부 확인, 포렌식 자료 확보 | 시스템 내부의 악성 행위 차단 |

### 클라우드, 가상화 환경

가상화는 물리 서버 한 대 안에 여러 대의 가상 머신을 만들어 쓰는 기술이고, 클라우드는 이런 자원을 인터넷으로 빌려 쓰는 서비스다. 같은 물리 서버 안의 가상 머신끼리 주고받는 트래픽은 물리 네트워크 장비를 거치지 않는다. 그래서 물리 장비로 둔 IDS나 IPS는 이 트래픽을 볼 수 없다. 이 환경에서는 IDS와 IPS를 가상 어플라이언스(가상 머신 형태의 보안 장비)로 두거나, 각 가상 머신에 호스트 기반 에이전트를 설치한다.

**IDS 활용**: 클라우드에서도 트래픽을 복사해서 IDS로 보낼 수 있다. 예를 들어 AWS의 VPC Traffic Mirroring은 가상 머신의 네트워크 트래픽을 복사해서 IDS가 설치된 가상 머신으로 보내 준다. 이 복사본으로 가상 머신 사이의 통신을 감시하고 기록한다.

**IPS 활용**: 클라우드 업체의 관리형 방화벽 서비스 중에는 IPS 기능을 함께 제공하는 것이 있다. 예를 들어 AWS Network Firewall은 Suricata 호환 규칙으로 트래픽을 검사해서 공격을 차단할 수 있다. 가상 네트워크(VPC)의 경계에 두고 들어오고 나가는 트래픽을 검사한다.

| 구분 | IDS | IPS |
|---|---|---|
| 위치 | 가상 어플라이언스, 트래픽 복사 기능과 연결 | 가상 네트워크 경계 (관리형 방화벽 서비스) |
| 주로 보는 트래픽 | 가상 머신 사이의 트래픽 | 가상 네트워크로 들어오고 나가는 트래픽 |
| 활용 | 가상 머신 간 통신 감시, 기록 | 클라우드 환경의 공격 차단 |

### 다층 보안 연계

보안 장비 하나에만 의존하면 그 장비가 뚫렸을 때 막을 수단이 없다. 그래서 여러 장비를 겹겹이 배치해서 한 계층이 뚫려도 다음 계층이 막도록 구성하는데, 이를 심층 방어(defense in depth)라고 한다. IDS와 IPS도 이 구성 안에서 다른 장비들과 역할을 나눈다.

| 계층 | 장비 | 역할 |
|---|---|---|
| 1 | DDoS 방어 서비스 | 대역폭을 가득 채우는 대규모 공격을 먼저 걸러냄 |
| 2 | 방화벽 | IP 주소, 포트 같은 헤더 정보로 허용할 통신을 정함 |
| 3 | IPS | 허용된 통신의 페이로드에 숨은 공격을 실시간으로 차단 |
| 4 | IDS | IPS가 놓쳤거나 판단이 애매한 활동을 감시하고 기록 |
| 5 | 호스트 기반 제품 | 서버 내부에서 실제로 일어나는 일을 확인하고 차단 |

각 장비의 경고와 로그는 SIEM(Security Information and Event Management)으로 모은다. SIEM은 여러 보안 장비와 시스템의 로그를 한곳에 모아 분석하는 시스템이다. 장비 하나의 경고만 보면 대수롭지 않아 보여도, 여러 장비의 이벤트를 시간 순서대로 엮어 보면 하나의 공격 흐름이 드러나기도 한다. 이 과정을 상관 분석이라고 한다.

IDS와 IPS는 이 안에서 다음처럼 일을 나눈다.

| 상황 | 맡는 쪽 | 이유 |
|---|---|---|
| 확실한 공격 | IPS | 바로 막아야 피해가 없음 |
| 판단이 애매한 활동 | IDS | 잘못 막으면 정상 서비스에 장애가 생김 |
| 새로 만든 탐지 규칙 | IDS로 먼저 운영 | 오탐이 없는지 검증한 뒤 IPS 차단으로 전환 |

어느 장비든 설치만으로 끝나지 않는다. 환경마다 정상 트래픽의 모습이 다르기 때문에 규칙을 끄고 켜거나 예외를 등록하는 조정을 계속해야 하고, 이 작업을 튜닝이라고 한다.

## 장단점

장단점을 보기 전에 두 용어를 알아 두면 좋다. 오탐(false positive)은 정상을 공격으로 잘못 판단하는 것이고, 미탐(false negative)은 공격을 정상으로 판단해서 놓치는 것이다.

| 구분 | IDS | IPS |
|---|---|---|
| 공격 대응 | 단점: 직접 차단하지 못함 | 장점: 실시간 자동 차단 |
| 오탐이 났을 때 | 장점: 경고만 발생 | 단점: 정상 통신이 차단됨 |
| 탐지 범위 | 장점: 민감한 규칙까지 적용 가능 | 단점: 확실한 규칙만 차단에 적용 |
| 통신 지연 | 장점: 없음 | 단점: 검사 시간만큼 지연 |
| 장비 장애 시 | 장점: 서비스는 정상 동작 | 단점: 네트워크가 끊길 수 있음 |
| 성능과 비용 | 장점: 상대적으로 부담이 적음 | 단점: 고성능 장비와 이중화 비용 필요 |
| 운영 부담 | 단점: 경고를 사람이 모두 분석해야 함 | 장점: 알려진 공격은 자동 처리 |

표를 보면 IDS의 장점이 IPS의 단점이 되고, IPS의 장점이 IDS의 단점이 된다. 두 시스템의 장단점은 트래픽 옆에 있느냐, 트래픽 위에 있느냐라는 같은 원인에서 나온다.

**탐지 범위**에서 차이가 나는 이유도 같다. IDS는 오탐이 나도 경고로 끝나기 때문에 공격 가능성이 조금만 있어도 잡아내는 민감한 규칙을 넓게 걸어 둘 수 있다. IPS는 오탐이 곧 서비스 장애로 이어지기 때문에 오탐 가능성이 낮은 확실한 규칙만 차단에 쓰고, 나머지는 경고만 하도록 설정하는 경우가 많다.

**성능과 비용**에서 IPS는 모든 트래픽을 회선 속도에 맞춰 실시간으로 검사해야 해서 처리 성능이 높은 장비가 필요하다. 또 장비 하나가 멈추면 전체 통신이 멈추는 단일 장애점이 되므로, 장비를 두 대 이상 두는 이중화나 장애 시 트래픽을 우회시키는 바이패스 장치가 필요하다. 장애 시 트래픽을 그대로 통과시키는 설정을 fail-open, 모두 막는 설정을 fail-closed라고 한다. fail-open은 서비스를 유지하는 대신 그동안 보호가 꺼지고, fail-closed는 보안을 유지하는 대신 서비스가 멈춘다.

**운영 부담**에서 IDS는 경고가 너무 많이 쌓이면 분석 인력이 다 확인하지 못해서 중요한 경고를 놓칠 수 있다. 이를 경고 피로(alert fatigue)라고 한다.

### 공통 한계

| 한계 | 내용 |
|---|---|
| 암호화 트래픽 | 네트워크 기반 제품은 암호화된 페이로드를 분석하지 못함 |
| 우회 기법 | 단편화, 인코딩 변경, 난독화로 서명을 피할 수 있음 |
| 알려지지 않은 공격 | 제로데이처럼 서명이 없는 공격은 둘 다 놓칠 수 있음 |
| 튜닝 필요 | 규칙을 꾸준히 조정하지 않으면 오탐과 미탐이 늘어남 |

## IDS와 IPS의 차이

| 구분 | IDS | IPS |
|---|---|---|
| 목적 | 탐지 | 탐지와 차단 |
| 배치 방식 | 수동 (트래픽 옆) | 인라인 (트래픽 위) |
| 분석하는 트래픽 | 복사본 | 원본 |
| 공격 대응 | 경고, 로그 기록 | 패킷 폐기, 세션 종료, IP 차단, 경고, 로그 기록 |
| 대응 시점 | 공격이 도착한 뒤 | 공격이 도착하기 전 |
| 오탐의 결과 | 불필요한 경고 | 정상 통신 차단 |
| 미탐의 결과 | 공격을 놓침 | 공격을 놓침 |
| 통신 지연 | 없음 | 있음 |
| 장비 장애 시 | 서비스 정상 | 통신 중단 가능 (fail-closed) |
| 잘 맞는 곳 | 분석과 감시가 중요한 구간 | 즉시 차단이 중요한 구간 |

### 방화벽과 비교

IDS와 IPS는 방화벽과도 자주 헷갈린다. 아래 표의 방화벽은 헤더 정보로 판단하는 전통적인 방화벽을 기준으로 한다.

| 구분 | 전통적인 방화벽 | IDS | IPS |
|---|---|---|---|
| 판단 기준 | IP 주소, 포트, 프로토콜, 연결 상태 | 페이로드와 통신 흐름 | 페이로드와 통신 흐름 |
| 검사 범위 | 패킷 헤더 | 패킷 전체 | 패킷 전체 |
| 질문 | 허용한 통신인가 | 공격으로 보이는가 | 공격으로 보이는가 |
| 대응 | 허용 또는 차단 | 경고 | 차단과 경고 |

전통적인 방화벽이 허용한 통신 안에 숨은 공격은 IDS와 IPS가 찾는다. 다만 요즘 많이 쓰는 차세대 방화벽(NGFW, Next-Generation Firewall)은 헤더뿐 아니라 애플리케이션 종류와 페이로드까지 검사하고, IPS 기능을 안에 포함하고 있다. 그래서 실제 환경에서는 방화벽과 IPS가 한 장비 안에서 동작하는 경우도 많다.

### 요즘의 IDS와 IPS

지금까지 IDS와 IPS를 나눠서 비교했지만, 실제 제품은 둘을 따로 만들지 않는 경우가 많다. 하나의 탐지 엔진이 두 모드를 모두 지원하고, 수동으로 배치하면 IDS로, 인라인으로 배치하면 IPS로 동작한다. Snort와 Suricata도 같은 프로그램을 설정에 따라 두 방식으로 쓸 수 있다. 그래서 둘을 합쳐 IDPS(Intrusion Detection and Prevention System)라고 부르기도 하고, 이 글에서 참고한 NIST 문서의 제목도 IDPS다.

인라인으로 배치한 IPS도 규칙마다 경고만 할지 차단할지를 정할 수 있다. 그래서 실제 운영에서 중요한 것은 "IDS를 쓸지 IPS를 쓸지"보다 "어떤 구간에 어떤 방식으로 배치하고, 어떤 규칙을 탐지로 두고 어떤 규칙을 차단으로 둘지"를 정하는 일이다.
