## 프로젝트 목표

소설 「프로젝트 헤일메리」를 모티브로 한 우주 테마 벽돌깨기 게임을 만드는 프로젝트였습니다. 일반 벽돌깨기에 산소(O₂) 시스템, 강화 벽돌, 아이템, 난이도 4단계를 더해 전략성을 높였습니다.

- **산소 시스템**: 게임 중 산소가 계속 줄어들고 0이 되면 게임이 끝납니다.
- **난이도**: Easy / Normal / Hard / Impossible에 따라 공 속도, 산소 감소 속도, 벽돌 수가 달라집니다.
- **화면 구성**: 캔버스를 배경, 게임, 효과 3개 레이어로 나눠 그렸습니다.

## 맡은 역할

- 버프/디버프 아이템 구현과 난이도별 등장 확률 조정
- 스토리 모드 구현 (컷씬, 스테이지 진행, 스테이지별 아이템 제한)
- 환경설정 화면 추가
- 종료하기 기능 구현
- 팀원 코드와의 병합 충돌 해결 및 중복 코드 정리

## 주요 구현

### 아이템 시스템

벽돌을 깨면 일정 확률로 아이템이 떨어지고 패들로 받으면 효과가 적용됩니다.

| 종류 | 아이템 | 효과 |
|---|---|---|
| 버프 | Wide Bar | 패들이 길어짐 (최대 길이 제한) |
| 버프 | ×3 | 공이 3개로 늘어남 |
| 디버프 | Small Ball | 공이 작아짐 |
| 회복 | 산소통 | 산소 회복 |

- 디버프 아이템은 난이도가 높을수록 자주 나오게 했습니다. (Easy에서는 나오지 않음)
- ×3 아이템을 만들려면 공이 여러 개 있어야 해서 공 하나를 담던 객체를 배열 구조로 바꾸고 이동, 충돌, 게임 오버 판정을 모두 배열 기준으로 수정했습니다. 모든 공이 떨어졌을 때만 게임이 끝나도록 했습니다.

### 스토리 모드

컷씬으로 이야기를 보여 준 뒤 스테이지를 진행하고 스테이지마다 난이도와 등장 아이템을 다르게 설정했습니다.

스토리 모드 코드는 별도 파일(`StoryModeJs.js`)로 분리했는데, 이 파일에서는 메인 게임 파일 안의 변수와 함수에 직접 접근할 수 없었습니다. 그래서 외부에서 써야 하는 기능만 `window.gameAPI` 객체에 담아 필요한 것만 공개하는 방식으로 연결했습니다.

## 문제와 해결

### 1. 컷씬을 넘긴 뒤 스페이스바를 누르면 컷씬이 다시 실행되는 문제

- **문제**: 컷씬의 "건너뛰기" 버튼을 클릭한 뒤 게임 중에 스페이스바를 누르면 버튼이 다시 눌려 컷씬이 재실행됐습니다.
- **원인**: 클릭한 버튼에 포커스가 남아 있어서 브라우저가 스페이스바 입력을 버튼 클릭으로 처리했습니다.
- **해결**: 버튼을 누른 직후 `blur()`로 포커스를 해제하고 게임이 시작되면 클릭 이벤트도 제거했습니다.

```javascript
skipBtn.blur();           // 스페이스바가 버튼을 다시 누르는 현상 방지
container.onclick = null; // 게임 시작 후 재실행 방지
```

### 2. 스토리 모드에서 아이템이 떨어질 때 생기는 에러

- **문제**: 특정 스테이지에서 벽돌을 깨면 에러가 발생했습니다.
- **원인**: 스테이지별로 등장 아이템을 제한하다 보니 아이템 목록이 빈 배열인 경우가 생겼고 빈 배열에서 무작위로 하나를 고르려다 에러가 났습니다.
- **해결**: 목록이 비어 있으면 아이템을 생성하지 않고 넘어가도록 검사를 추가했습니다.

```javascript
// 드롭 가능한 아이템이 없으면 스킵
if (buffTypes.length === 0 && debuffTypes.length === 0) return;
```

### 3. 다음 스테이지에 이전 스테이지 문구가 남는 문제

- **문제**: 다음 스테이지 컷씬이 시작돼도 이전 스테이지의 클리어 메시지가 화면에 남아 있었습니다.
- **원인**: 메시지를 그린 효과 레이어 캔버스를 지우지 않고 다음 화면을 그렸습니다.
- **해결**: 컷씬을 시작할 때 효과 캔버스를 `clearRect()`로 비웠습니다.

## 아쉬운 점

### 스토리 모드의 완성도

시간이 부족해서 스토리 모드를 충분히 다듬지 못했고 결과적으로 완성도가 낮게 나왔습니다.

### 세분화되지 않은 파일 구조

게임의 대부분 코드가 하나의 파일에 들어 있어서 Git으로 공유하면서 수정할 때 불편했고 코드의 가독성도 좋지 않았습니다. 기능별로 파일을 나눠 두었다면 함께 수정하기도, 코드를 읽기도 더 수월했을 것 같습니다.

## 배운 점

### 팀 내 소통의 중요성

이번 프로젝트는 팀원 간 소통이 많지 않았고 그 때문에 진행 속도가 잘 나지 않았습니다. 진행이 늦어지자 남은 시간에 쫓겨 각자 해야 할 작업을 처리하기 바빴고 팀원들에게 제 의견을 말하고 싶어도 그럴 여유가 없는 상황이 생겼습니다. 소통이 부족해 진행이 늦어지고 진행이 늦어져 다시 소통할 여유가 없어지는 악순환이 이어진다는 것을 느꼈습니다.

이 경험을 통해 팀 프로젝트에서는 소통이 중요하다는 것을 알게 되었습니다.
